## 2. Question bank (10 new)

**Q1 · Capability Maps · Foundational** — correct: index 1
A business capability map answers which question?
1. Who reports to whom on the org chart
2. What the business is able to do (its capabilities), independent of how or who
3. Which software vendors are under contract
4. What the current sprint backlog contains
**a: 1** — *A capability map describes WHAT a business can do (stable abilities like "Customer Onboarding"), decoupled from process, org structure, and tools — a stable backbone for analysis and transformation.*

**Q2 · Value Streams · Practitioner** — correct: index 2
A value stream is best described as:
1. A list of departments
2. A budget allocation
3. The end-to-end sequence of activities that delivers value to a customer/stakeholder
4. An organization chart
**a: 2** — *A value stream is the end-to-end set of value-adding activities producing a result for a customer — cutting across functions, and the lens for finding cross-functional waste and improvement.*

**Q3 · Operating Models · Practitioner** — correct: index 0
An operating model defines:
1. How an organization combines people, process, technology, structure, and governance to deliver its strategy
2. The quarterly revenue target
3. The UI design system
4. The sprint cadence
**a: 0** — *An operating model describes HOW the organization is configured to execute strategy — the bridge between strategy and execution.*

**Q4 · Organization Design · Practitioner** — correct: index 3
When recommending an org-design change to support a new operating model, the BA's primary concern is:
1. Reducing headcount as much as possible
2. Copying a competitor's structure
3. Choosing the trendiest structure
4. Aligning structure, roles, decision rights, and incentives to the target capabilities and value streams
**a: 3** — *Org design must align structure, roles, decision rights, and incentives to the capabilities/value streams the strategy requires — not headcount-cutting, imitation, or fashion.*

**Q5 · Target-State Architecture · Foundational** — correct: index 1
A target-state (to-be) business architecture represents:
1. The current state documented in detail
2. The desired future configuration of capabilities, processes, and structure that supports the strategy
3. A list of current problems
4. The IT network diagram
**a: 1** — *Target-state architecture defines the future configuration the organization is transforming toward — the destination a roadmap closes the gap to.*

**Q6 · Transformation Roadmaps · Practitioner** — correct: index 2
A transformation roadmap is most credible when it is:
1. A single big-bang cutover with no phases
2. Organized purely by software releases
3. Sequenced by capability gaps, dependencies, value, and risk into phased waves
4. A list of features with no dependencies
**a: 2** — *A defensible roadmap sequences the current→target gap into phased waves driven by capability gaps, dependencies, value delivery, and risk — not big-bang cutovers or release-only views.*

**Q7 · Capability Heatmaps · Foundational** — correct: index 0
A capability heatmap is used to:
1. Visually highlight which capabilities are strong vs weak/at-risk, to focus investment
2. Track server temperature
3. Show the sprint burndown
4. Display the org-chart hierarchy
**a: 0** — *A heatmap overlays maturity/performance/risk onto the capability map, directing transformation investment to the highest-need areas.*

**Q8 · Strategic Alignment · Senior** — correct: index 3
An executive asks a BA to justify a transformation investment. The most strategically aligned justification traces the initiative to:
1. The newest technology trend
2. What a competitor announced
3. The number of features delivered
4. A specific strategic objective and the capability gap it closes, with the expected measurable outcome
**a: 3** — *Strategic alignment links each initiative to a stated objective and the capability gap it closes, with the measurable outcome — the language executives fund, unlike trend/competitor/output rationales.*

**Q9 · Enterprise Change Design · Practitioner** — correct: index 1
Designing enterprise change for a new operating model, the BA must address:
1. Only the technology rollout
2. People, process, technology, and governance changes together, plus stakeholder adoption and impact
3. Only the training schedule
4. Only the new org chart
**a: 1** — *Enterprise change is socio-technical: people, process, technology, and governance must change together, with deliberate adoption and impact management — a tech-only or org-only view fails.*

**Q10 · Executive Transformation Planning · Senior** — correct: index 2
At the executive level, the strongest transformation plan a BA can present is one that:
1. Lists every task in the program
2. Focuses on tooling decisions
3. Connects strategy → target capabilities → phased roadmap → investment → measurable outcomes and risks
4. Defers all decisions to the vendor
**a: 2** — *Executive transformation planning tells a coherent strategy-to-outcome story (strategy → capabilities → roadmap → investment → outcomes/risks) — the board-level narrative, not a task list or tooling focus.*
