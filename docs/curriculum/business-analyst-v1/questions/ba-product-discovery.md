## 2. Question bank (15 new)

**Q1 · Opportunity Solution Trees · Practitioner** — correct: index 2
In Teresa Torres's Opportunity Solution Tree, what sits directly beneath the desired outcome?
1. Solutions
2. Experiments
3. Opportunities — unmet needs, pain points, desires
4. Roadmap dates
**a: 2** — *An OST flows outcome → opportunities → solutions → experiments. Opportunities sit beneath the outcome; solutions address opportunities, never the outcome directly.*

**Q2 · Jobs To Be Done · Foundational** — correct: index 0
The JTBD lens frames a customer need as:
1. The progress a customer is trying to make in a given circumstance
2. The specific features they request
3. Their demographic profile
4. The competitor they currently use
**a: 0** — *JTBD focuses on the underlying progress a customer "hires" a product to achieve, independent of features/demographics — surfacing the real need.*

**Q3 · Outcome vs Output · Foundational** — correct: index 2
Which of these is an outcome, not an output?
1. Ship a new onboarding screen
2. Release five features this quarter
3. Reduce time-to-first-value so 20% more users activate
4. Write 30 user stories
**a: 2** — *Outputs are what you build/ship; outcomes are measurable changes in behavior. Discovery targets outcomes (activation lift), not output counts.*

**Q4 · Assumption Mapping · Practitioner** — correct: index 0
When assumption-mapping a new idea, which assumptions should be tested first?
1. High-importance, high-uncertainty (leap-of-faith) assumptions
2. The easiest ones to test
3. The ones the team likes most
4. Low-risk assumptions
**a: 0** — *Prioritize leap-of-faith assumptions — high impact + high uncertainty — because they carry the most risk. Testing easy/low-risk ones first wastes discovery effort.*

**Q5 · Hypothesis & Experiment Design · Practitioner** — correct: index 1
A well-formed discovery hypothesis is best expressed as:
1. "Users will love this."
2. "We believe [change] will achieve [measurable outcome] for [segment]; we'll know if [signal]."
3. "We should build feature X."
4. "The market is big."
**a: 1** — *A testable hypothesis names the change, expected measurable outcome, segment, and success signal — making it falsifiable. Vague beliefs/solution statements aren't testable.*

**Q6 · MVP Definition · Practitioner** — correct: index 3
The purpose of an MVP in discovery is to:
1. Ship a smaller version of the final product
2. Impress stakeholders
3. Cut scope to hit a deadline
4. Learn the most about a risky assumption with the least build
**a: 3** — *An MVP is a learning vehicle — the smallest thing that validates/invalidates a key assumption. It maximizes validated learning per unit of effort, not just a smaller release.*

**Q7 · Discovery Interviews · Foundational** — correct: index 0
In a discovery interview, the strongest question is:
1. "Tell me about the last time you faced [problem] — what did you do?"
2. "Would you use a feature that does X?"
3. "Do you like this idea?"
4. "How much would you pay for it?"
**a: 0** — *Story-based, past-behavior questions surface real evidence. Hypothetical/leading questions produce courtesy-biased, unreliable answers.*

**Q8 · Signal vs Noise · Practitioner** — correct: index 1
Treating one enthusiastic customer's feature demand as a roadmap mandate risks:
1. Ignoring all feedback
2. Mistaking noise (an anecdote) for signal (a validated pattern)
3. Over-researching the problem
4. Building too slowly
**a: 1** — *One loud request is an anecdote, not validated demand. Discovery separates signal (recurring, evidenced patterns) from noise (isolated opinions).*

**Q9 · Behavioral Evidence · Practitioner** — correct: index 2
Which is the strongest evidence of a real need?
1. Stated intent on a survey
2. A focus-group consensus
3. Observed behavior — what users actually do, including current workarounds
4. A senior stakeholder's opinion
**a: 2** — *Behavioral evidence outranks stated intent (prone to bias). Surveys/opinions are weaker supporting signals; what people actually do is the strongest.*

**Q10 · Working Backwards / PR-FAQ · Practitioner** — correct: index 0
Amazon's Working Backwards PR/FAQ forces a team to:
1. Articulate the customer value and experience before building anything
2. Write press releases for the marketing team
3. Skip discovery and start coding
4. Finalize the architecture first
**a: 0** — *A PR/FAQ written before build clarifies the customer problem, value, and experience up front — exposing weak ideas early and aligning on outcomes, not features.*

**Q11 · Opportunity Prioritization · Senior** — correct: index 3
Across many discovered opportunities, the most defensible prioritization weighs:
1. First-come, first-served
2. The CEO's personal favorite
3. Whatever is easiest to build
4. Outcome impact, strength of evidence, and addressability — not seniority or the loudest voice
**a: 3** — *Mature prioritization weighs potential outcome impact, how strongly evidence shows the opportunity is real, and how addressable it is — an evidence-based call, not politics.*

**Q12 · Value vs Effort · Foundational** — correct: index 1
A value-vs-effort matrix helps a team:
1. Estimate exact delivery dates
2. Spot high-value, low-effort opportunities to pursue first
3. Replace discovery entirely
4. Measure team velocity
**a: 1** — *Value/effort mapping is a fast triage heuristic to surface quick wins and de-prioritize low-value/high-effort items — a prioritization aid, not a delivery estimate.*

**Q13 · AI Interview Synthesis · Practitioner** — correct: index 2
A BA uses AI to synthesize 20 discovery interviews into themes. The essential safeguard is:
1. Accept the themes if they sound coherent
2. Use only the AI summary going forward
3. Trace each AI-identified theme to actual interview evidence and check for omitted dissent
4. Keep the themes that best fit the existing roadmap
**a: 2** — *AI synthesis can fabricate or flatten signal. Validating themes against real evidence — and checking for dropped minority/contradictory data — keeps discovery honest (links to `ba:ai-prompting`).*

**Q14 · Pattern Detection & Opportunity Clustering · Senior** — correct: index 0
AI clusters discovery data into opportunity groups. The senior BA's most important critical check is:
1. Whether clusters reflect genuine user patterns vs surface-level keyword similarity — and whether important outliers were hidden
2. Whether there are exactly five clusters
3. Whether the chart looks clean
4. Whether it matches last quarter's themes
**a: 0** — *AI clustering can group on superficial similarity and bury meaningful outliers (often where new opportunities live). The BA validates that clusters represent real, decision-relevant patterns.*

**Q15 · AI-Assisted Research Validation · Senior** — correct: index 3
AI surfaces a "strong opportunity," but it rests on three untested assumptions. The correct next step is:
1. Add it to the roadmap immediately
2. Trust the AI's confidence score
3. Ask the AI to re-rank the opportunities
4. Design experiments to test the riskiest assumptions before committing — AI surfacing it is not validation
**a: 3** — *AI can surface and rank candidate opportunities but cannot validate them. The BA still tests the riskiest assumptions with real evidence before commitment.*
